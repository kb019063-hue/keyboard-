# Keyboard bug audit — 2026-10-25

## Why this audit exists

The owner reported that the keyboard still had "so many issues and bugs" without naming them. I
started from the last green CI run rather than guessing: run `40158863964` passed, but its own
annotations said

- `MTSHEET skipped, tap at 169 1354 logged nothing`, and
- `VOICE skipped, coordinate tap at 910 1354 logged no dictation press`.

Those are taps on the first and last toolbar buttons. The row rendered, but neither press reached
the command dispatcher. The smoke harness deliberately stands these checks down when a tap is
silent, so a completely dead toolbar could still produce a green run. That led to the rest of this
audit.

## Findings and fixes

| # | Severity | Symptom / root cause | Fix |
|---|---|---|---|
| 1 | Critical | All seven icon toolbar buttons were dead. `KeyboardToolbar.createIconButton` made the inner `ImageView` clickable/focusable **and** put the click listener on its `FrameLayout` wrapper. A clickable child consumes `ACTION_UP`, so the parent listener never fires. This matches the two silent CI taps. | The wrapper now owns the click, ripple, long-press label, tooltip, accessibility label and 40 dp minimum hit target. The `ImageView` is non-clickable, non-focusable and hidden from accessibility. |
| 2 | High | The icon was drawn in a 22 dp box with 8 dp padding on both sides, leaving a 6 dp glyph. Icon wrappers also had no 40 dp minimum width despite the class doc promising one. | Icons are a real 24 dp with no internal padding; every wrapper has `minimumWidth = 40dp`. |
| 3 | Medium | `redo` reused `ic_tool_undo`, so a custom toolbar with both commands showed two identical left arrows. | Added a mirrored `ic_tool_redo` vector and mapped `redo` to it. |
| 4 | High | Compact mode kept only `more_tools` and `voice_typing` by name. A custom toolbar without those commands lost every button while suggestions were showing. The two survivors each took half the row, so they sat at 25%/75% rather than the edges. | Added pure, unit-tested `ToolbarCompactPolicy`: keep the first and last rendered buttons by position, pin them to intrinsic width, and put a flexible spacer between them. This also puts the buttons under the smoke harness's edge tap coordinates. |
| 5 | Medium | A corrupt or stale `toolbar_keys` value containing only unknown commands parsed to an empty list, and `KeyboardToolbar.applyFromConfig` hid the whole toolbar. | `ToolbarConfig.parse` falls back to the seven defaults when every token is invalid. |
| 6 | High | `DictationController.destroy()` existed but was never called. A failed `startListening`/`stopListening` also held transient audio focus with no callback left to release it. The `SpeechRecognizer`, audio route and service context could outlive the IME. | Added `KeyboardReceiver.destroy()`, wired it to `CleverKeysService.onDestroy`, and released audio focus on every terminal failure/cancel path. |
| 7 | Medium | The more-tools sheet recomputed each toggle from `_config`. Two fast taps on one row could both read the same pre-listener value and write the same state twice, while the dialog checkbox showed the opposite. | Added explicit `set*Enabled(value)` methods and made the sheet pass its own `isChecked` value. The public command toggles now delegate to those setters. |
| 8 | High | Thirteen phase 1–4 preferences were absent from `SETTINGS_DEFAULTS`: sound, incognito, floating, split, voice typing, calm labels and suggestion-strip visibility. Fresh-install imports showed them as unclassified `ADDED` rows and the defaults were missing from the export seed. `SettingsDefaultsDriftTest` would fail. | Added all thirteen typed defaults, plus import ranges for the new integer/float settings and float classification for the floating-window fractions. |
| 9 | High (privacy) | Clipboard password-manager exclusion cached the foreground package for two seconds. A copy in a password manager followed by a paste in another app inside that window could inherit the wrong app's answer. | `onStartInputView` now passes `EditorInfo.packageName` to the clipboard catch-up. The UsageStats fallback remains only for OS clipboard listener callbacks and is no longer cached. |
| 10 | Medium | `floating_x_fraction` / `floating_y_fraction` used raw `getFloat`, and the mic preference reads used raw `getString`/`getBoolean`. A wrong-typed pref from import or hand editing could throw `ClassCastException` during `Config.refresh` or on a mic press. | Switched those reads to `Config.safeGetFloat/safeGetString/safeGetBoolean`. |
| 11 | Medium | `KeyClickSound.release()` ran from every `Keyboard2View.onDetachedFromWindow`. A settings theme-preview view detaching could release the native `SoundPool` the live IME was still using. | Release moved to `CleanupHandler` (service destroy); stale documentation corrected. |
| 12 | Medium | `latn_qwerty_us_gboard_style.xml` declared `loc esc` twice. `KeyboardData.getKeys()` is keyed by `KeyValue`, so one placement was silently overwritten. | Removed the duplicate on Q; `esc` remains on backspace. Added a production-parser regression test. |
| 13 | Medium | `tools/check_layout.py` was not a real build gate: Gradle called it during configuration with `ignoreExitValue = true`, and `assembleDebug` did not depend on its task. Its known-key parser also used Java regexes against Kotlin `when` branches, reporting almost every special key as unknown. | The checker is now a real `preBuild` task action; duplicates exit non-zero. It parses Kotlin branch literals and resolves `label:key` syntax such as `?123:switch_numeric`. Advisory warnings remain non-fatal. |
| 14 | Low | `onDestroy` never unregistered the two `SharedPreferences` listeners, and `SuggestionBar` still carried an unused divider pool plus comments claiming dividers were drawn. | Listeners are unregistered; dead divider code and stale comments removed. |

## Regression coverage added

- `ToolbarCompactPolicyTest` — normal, compact, custom, one-button and empty toolbars.
- `SettingsDefaultsDriftTest.phaseFourFeaturePreferencesHaveTypedBackupDefaults` — all thirteen
  new keys and representative types.
- `StyleLayoutsTest.gboardStyleHasNoDuplicateKeyValues` — parses the real layout and asserts every
  declared value keeps exactly one position.
- `CoreImeHygieneDriftTest` — updated to require that the clipboard catch-up receives
  `info.packageName`.
- `tools/check_layout.py` — duplicate values now fail `assembleDebug`; the false-positive special-key
  warnings are gone (the remaining `julow` word-suggestion warnings are intentional string keys).
- `docs/PHASE4-POLISH-DESIGN.md` part 7 and `AGENTS.md` document the corrected behaviour.

## Local verification

- `python3 tools/check_layout.py` → exit 0, **0 duplicate-key warnings**, 27 advisory warnings.
- All XML under `res/`, `src/main/layouts/` and the manifest parse cleanly.
- `python3 -m compileall` for `scripts/` and `tools/` succeeds; all shell scripts pass `bash -n`.
- Tree-sitter parsed 981 Kotlin sources. The eight files it cannot parse are pre-existing grammar
  limitations and reproduce on the untouched upstream snapshot; none of the changed/new Kotlin
  files have a syntax error.
- A 15-point source invariant scan passes (toolbar touch ownership, icons, compact policy,
  dictation lifecycle, clipboard editor package, backup defaults, more-tools state, sound-pool
  ownership, duplicate layout key and build-gate wiring).

## Remaining known gaps

- The installed APK is still the unminified, debuggable debug variant. That is the largest
  remaining performance gap; changing it requires a separate release/backup-migration decision.
- The toolbar and suggestion strip are still sibling views. Compact mode now puts the two end
  buttons at the edges with a flexible middle, but a true `[grid][words][mic]` row needs an
  input-view hierarchy change.
- In-service dictation depends on the device's `SpeechRecognizer`, `RECORD_AUDIO` permission and
  OEM microphone policy. Audio-focus and locale hints are now requested, but no offline IME can
  manufacture a recogniser that the device does not provide.
- The emulator smoke harness still stands down dump-blind IME-window assertions. With the toolbar
  click bug fixed, its first/last-button taps should now emit `MoreToolsSheet: press` and
  `DictationController: press` instead of `log='none'`.
